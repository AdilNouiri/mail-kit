# T1 decisions — theme validation and fixed strings

Date: 27 November 2026.

## D1 — Checked contrast pairs (completes)

Light: `onBrand`/`brand`, `onAccent`/`accent`, `footerText`/`canvas`, `text`, `textSoft`,
`muted`, `link` on `card`, `text` and `textSoft` on `subtle`. Dark: the same set minus the
brand, accent and footer pairs, plus `dark.muted` on `dark.canvas` (the dark footer
colour, added by spec commit 4c6f197). Ratio unrounded, limit 4.5
inclusive. The `ThemeError.path` is the foreground field (`colors.onAccent`); the message
names both fields and the ratio to two decimals.

## D2 — Validation order and details (completes)

First failure throws; fields are read in model order, contrast runs after every shape check.
Unknown fields are refused at every object level (`colour`, `colors.acent`, `logo.src`).
Hex is `#rrggbb`, either case, kept as given. Logo and web font extensions are read from the
URL path (query string ignored, case-insensitive). The generic family is the last
comma-separated token of the stack, case-insensitive. Web font paths are `webFonts[0].url`.
Numbers must be finite; `wordmarkSpacing`, `buttonRadius` and logo sizes are not forced to
integers.

## D3 — `src/i18n.ts` shape (completes)

`stringsFor(lang)` gives `{ fallbackLead, codeLabel, colon }`; `labelled(lang, label, value)`
builds `Me connecter : url` (fr) or `Sign in: url` (en), also `Code : 482 913`. T2 uses
`fallbackLead`, T3 uses `labelled` and `codeLabel`.

## Found for T4 (themes.json is not a ThemeInput)

`spec/images/src/themes.json` uses `logo.src` (relative asset), `webFonts` as a CSS string,
and `wordmarkSpacing` as `"3px"`. T4 must build real `ThemeInput` objects: `logo.url`
absolute `https:` PNG/JPEG, `webFonts` as `{ family, url, weight }[]`, `wordmarkSpacing: 3`.
The T1 test converts those three fields (logo to an example.com URL, spacing to a number,
web fonts dropped) and every colour, font and footer value of both themes passes.
