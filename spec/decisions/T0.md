## D1 — `@cloudflare/vitest-plugin` instead of `@cloudflare/vitest-pool-workers` (departs)

`npm view @cloudflare/vitest-pool-workers deprecated` says: "has been renamed to
@cloudflare/vitest-plugin. This package will not receive future updates." Its last
version (0.23.0) needs vitest `^4.1.0`; the plugin needs `^4.1.0 || ^5.0.0`, and Majordome's
app now uses the plugin 1.9.2 with vitest 5.1.2, which is the reason the spec gave
("the fixture matches its setup"). Proposed spec change: in `07-architecture.md` 7.2,
`09-tests.md`, `03-features.md` F6.2 and `11-tasks.md` T0, read `@cloudflare/vitest-plugin`
where `@cloudflare/vitest-pool-workers` is written.

## D2 — Placeholder modules (completes; Files lines to update)

`src/index.ts`, `src/render-mail.ts` and `src/themes/index.ts` are written against the
modules other tasks own, so T0 creates each of them as a minimal placeholder that
type-checks and throws `not built yet (Tn)` when called (functions) or when imported
(constants). The owning task replaces the whole file and keeps the exported name and
signature:

| Placeholder | Export and signature kept | Owner |
| --- | --- | --- |
| `src/theme.ts` | `defineTheme(input: ThemeInput): Theme` | T1 |
| `src/html/index.ts` | `renderHtml(theme: Theme, content: MailContent): string` | T2 |
| `src/text.ts` | `renderText(theme: Theme, content: MailContent): string` | T3 |
| `src/themes/majordome.ts` | `majordome: Theme` | T4 |
| `src/themes/dream-studio.ts` | `dreamStudio: Theme` | T4 |
| `src/samples.ts` | `samples: Samples` | T4 |

Proposed spec change: add these six paths to T0's **Files** line (they already sit on the
owners' lines). The theme and sample placeholders throw at import, so nothing may import
them before T4; nothing in T1, T2 or T3 needs to.

## D3 — Content checks live in `renderHtml`; `renderMail` calls it first (completes)

T2 owns the content checks (`ContentError`, F2.4 and the 4.2/4.3 limits, CR or LF in the
subject). `renderMail` calls `renderHtml` before `renderText`, so every error reaches the
consumer through `renderMail`, and T2 can test them through `renderMail` while `text.ts` is
still a placeholder. `renderText` may assume valid content. Proposed spec change, 06-api.md
6.1, `renderText` errors: "none of its own: it expects content `renderMail` accepts".
Alternative, if the architect prefers every exported function to check on its own: a T0
follow-up adds `src/content.ts` (`checkContent`) with its test, and T2 and T3 both call it.

## D4 — Imports carry the `.ts` extension (completes)

Relative imports are written `./theme.ts`; `tsconfig.json` sets `allowImportingTsExtensions`
and `rewriteRelativeImportExtensions`, so `tsc` emits `./theme.js` in `dist/*.js`, and Node
24 runs `scripts/*.ts` and `test/assumptions/*.ts` directly (type stripping, no `tsx`).
`erasableSyntaxOnly` keeps every file strippable. Checked on 27 Nov 2026: an emit of `src/`
with `tsc --ignoreConfig ... --rewriteRelativeImportExtensions --declaration` gives `.js`
imports in the `.js` files; the `.d.ts` files keep `.ts`, and a consumer type-checks
against them under both `moduleResolution: nodenext` and `bundler` (tsc 7.0.2); Node
imports the emitted package.

## D5 — One `tsconfig.json`, `src/` safety by Biome (completes)

`tsconfig.json` covers `src`, `test`, `scripts` and `vitest.config.ts` with `lib` es2022 +
dom and `types` node, since tests and scripts need both (Playwright page callbacks, Node
APIs). Worker safety of `src/` is enforced by a Biome override on `src/**`:
`noNodejsModules`, `noUndeclaredDependencies` with dev, peer and optional dependencies
refused (so any package import fails), `noRestrictedGlobals` (`document`, `window`,
`navigator`, `process`, `Buffer`, `require`, `fetch`, `Date`, `crypto`) and `noConsole`.
Checked on 27 Nov 2026 with a probe file in a scratch copy: every rule fires under `src/`
and none under `test/`. The release build (T6) compiles `src/` alone with `--lib es2022
--types ""`, which also proves no DOM or Node type leaks in; checked by the emit of D4.
`test/consumers` and `test/assumptions/worker-file-dep` are excluded from `tsconfig.json`
(their imports resolve only after their own install).

## D6 — The `Theme` brand is type-only (completes)

`Theme` carries `readonly [themeBrand]: true` where `themeBrand` is a `declare const ...:
unique symbol`: a plain object literal is refused by the compiler, and no symbol exists at
run time. `defineTheme` (T1) returns its frozen object cast to `Theme`; T2's test helper
casts the same way. `renderMail` does not re-validate a theme at run time.

## D7 — Shapes the data model leaves open (completes)

- `Theme` is the resolved form: `wordmarkSpacing` 0, `lang` `"en"`,
  `fonts.displayWeight` 700, `buttonRadius` 8 and `webFonts` `[]` are filled in by
  `defineTheme`; `logo` and `footer.link` stay absent when absent. `ThemeInput` has the
  same fields with the defaulted ones optional.
- Colours are `string` (`HexColor` alias), not a template literal type: validation is
  `defineTheme`'s, and tests of bad colours need no cast.
- `WebFont.weight` is `100 | 200 | ... | 900`; `fonts.displayWeight` is `400 | 600 | 700`.
- `Inline` is `string | { bold } | { text, url }`; `RichText` is `string | readonly Inline[]`.
  One interface per block (`HeadingBlock`...), `Block` is their union on `type`.
- `ThemeError(path, message)`; `ContentError(field, message, blockIndex?)`: `field` is
  the field inside the block when `blockIndex` is set (`url`), else the content's field
  (`subject`, `blocks`). `message` is the plain message, without the path.
- Extra exported types: `Lang`, `HexColor`, `DisplayWeight`, `FontWeight`, `Logo`,
  `ThemeColors`, `ThemeDarkColors`, `ThemeFonts`, `ThemeFontsInput`, `WebFont`,
  `FooterLink`, `ThemeFooter`, `RichText`, `BlockType`, `BuiltInThemeId`, `SampleName`,
  `Samples`.
- `VERSION` is a constant in `src/types.ts` (`"0.1.0"`), equal to `package.json`'s
  `version`; T6's release script must update both.

## D8 — `src/escape.ts` (completes)

`escapeHtml` escapes `& < > "` (F2.3's expected output; apostrophes stay, French text
keeps `'`), `escapeAttribute` also escapes `'`. `isAllowedUrl(url, schemes)` is the one URL
check for T1 (`["https:"]`) and T2 (`["https:", "mailto:"]`): absolute, `https://` with a
host, or `mailto:` with an address, and no whitespace or control character (the URL
parser would strip them silently). It uses the `URL` global, present in Workers and Node.

## D9 — `src/themes/index.ts` (completes)

It re-exports `majordome` and `dreamStudio` and exports
`builtInThemes: Readonly<Record<BuiltInThemeId, Theme>>`, keyed by theme `id`, for the
preview (T5), the lint tests and `send-test --theme <id>` (T7). Being under
`./themes/*`, it is also importable as `mail-kit/themes/index`.

## D10 — Package shape (completes)

- `"private": true` (no npm publish, decision 3; git installs still work), `"type":
  "module"`, `"sideEffects": false`, `"files": ["dist"]`, `engines.node` `>=22.12.0` (same
  floor as Majordome). No `prepare` or `install` script (F6.1).
- `exports`: `.` → `dist/index.{js,d.ts}`, `./themes/*` → `dist/themes/*.{js,d.ts}`,
  `./samples` → `dist/samples.{js,d.ts}`; `types` listed first in each.
- Development runs on Node 24 (installed: 24.22.0); consumers need Node 22.12 or later.

## D11 — The check command (completes)

`npm run check` = `lint` (`biome check .`) → `typecheck` (`tsc --noEmit`) → `test`
(`vitest run`) → `test:worker` → `test:node` → `preview` → `test:mockup`. The last four are
no-op `node -e` scripts printing which task fills them (T6, T6, T5, T5); those tasks
replace the script text and keep the names. `vitest.config.ts` runs `test/**/*.test.ts`
except `test/assumptions/**` and `test/consumers/**`, with at most 4 workers. Biome skips
`spec/`, `assets/`, Markdown and the lockfile.
