# T6 decisions — release, consumer fixtures, README

Date: 27 November 2026.

## D1 — Release build uses `--lib es2022,dom` (departs from T0 D5)

`decisions/T0.md` D5 says the release build compiles `src/` with `--lib es2022 --types ""`.
With tsc 7.0.2 that fails: `src/escape.ts` and `src/theme.ts` use `URL`, which only the
`dom` or Node libs declare. `dom` is the smaller leak, and `URL` exists in Workers and
Node. The emitted `.d.ts` files reference no DOM type. `scripts/release.ts` therefore
passes `--lib es2022,dom --types ""`. Biome still bans DOM globals in `src/`.

## D2 — Release flow

- Works in a temporary clone of the repository's committed HEAD (uncommitted changes are
  not released). Real mode needs branch `main`, a clean tree and an unused tag; it pushes
  the cleanup commit to `main` and the tag in one `git push` to `origin`. `--dry-run` does
  the same in the clone and pushes nothing; `--pack <dir>` also writes the `npm pack`
  tarball of the release commit.
- The release commit adds `dist/` with `git add --force` (ignored on the default branch);
  the tag points at it; the next commit removes it from the index (F6.1).
- The script refuses a `src/types.ts` `VERSION` that differs from `package.json` (F6.5).

## D3 — Fixtures

`npm run test:worker` and `test:node` both run `test/consumers/prepare.ts`, which makes a
dry-run build, packs it and installs the tarball (`--no-save`, `--ignore-scripts`) into
`test/consumers/<fixture>/node_modules` (ignored). The Worker fixture runs under
`@cloudflare/vitest-plugin`; the Node fixture is plain `.mjs` for `node --test`. F6.1,
F6.4 and F6.5 are tested in `test/consumers/release/release.test.ts` (run by `test:node`,
since `vitest` excludes `test/consumers/**`); it installs the tag from a `git+file://` URL
without `--ignore-scripts`. The Node 22 run is not exercised here: the Mac has Node 24.
