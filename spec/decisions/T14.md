# T14 decisions: plain fixes

Date: 28 November 2026.

## D1: `Intl.Segmenter` is used

The text part counts grapheme clusters with `Intl.Segmenter` (F3.5), created once at module
load. It exists in Node 22 and later; the Worker consumer fixture of the check proves it in
`workerd`. If that fixture fails, the fallback is to count code points and record it here.

## D2: The note link colour is passed to the rich-text renderer

`renderRichText` takes an optional `linkColor`; `renderNote` passes `textSoft`, so the inline
style of a link in a note is the note's own text colour. The dark rule `.mk-note .mk-link`
(and its `[data-ogsc]` copy) follows `.mk-link` and wins by specificity.

## D3: Lint and browser cases come from the built-in themes and samples

`test/lint/*.test.ts` use `builtInThemes` and `samples` (in the theme's language), plus the
`notice` fixture for the link block and inline link no sample holds, and a small note-link
fixture of their own. The F4.6 sanity floor on the number of text pairs drops from 5 to
3: the real Dream Studio theme has no logo or footer link, so its smaller mails hold 5 pairs.

## D4: The size limit counts the html only

`renderMail` refuses above 100,000 UTF-8 bytes of html; `renderText` is unaffected, since the
text part is not what Gmail clips.
