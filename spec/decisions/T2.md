# T2 decisions — HTML layout and blocks

Date: 27 November 2026. Each entry: the choice, its reason, and whether it completes or
departs from the spec.

## D1 — Module layout (completes)

`src/html/index.ts` (`renderHtml`, the document frame), `check.ts` (`checkContent`, every
`ContentError`), `layout.ts` (preheader, banner, accent rule, footer), `style.ts` (the
`<style>` block and the Outlook style), `css.ts`, `rich-text.ts`, `fallback-lead.ts`, and
one module per block in `src/html/blocks/`. The markup and inline styles are the mockup
generator's (`spec/images/src/build-mockups.mjs`); differences are listed below.

## D2 — Fallback lead is a local stub (stub to switch at merge)

`src/html/fallback-lead.ts` holds the fr and en leads of F2.5, word for word from the spec.
T1's `src/i18n.ts` (built in parallel) owns these strings: at merge, the button module
imports the lead from `i18n.ts` and `fallback-lead.ts` is deleted.

## D3 — Outlook VML button (completes)

Pattern: Campaign Monitor's "Bulletproof email buttons" generator (`https://buttons.cm/`),
the VML variant described in Litmus's "A guide to bulletproof buttons in email design"
(`https://www.litmus.com/blog/a-guide-to-bulletproof-buttons-in-email-design`). Cited from
knowledge; the pages were not re-fetched during this task. The markup:
`<!--[if mso]><v:roundrect xmlns:v xmlns:w href=… style="height;v-text-anchor:middle;width"
arcsize stroke="f" fillcolor=accent><w:anchorlock/><center>label</center></v:roundrect><![endif]-->`,
then the mockup's table-cell button inside `<!--[if !mso]><!-->…<!--<![endif]-->`, so
Outlook draws one button only. VML needs a fixed size: height 48 px (14 + 20 + 14), width
estimated as 9 px per label character + 56 px of padding; `arcsize` is
`buttonRadius / 24` as a percentage, capped at 100 % (999 → pill). The roundrect sits in a
`<div style="margin:8px 0 24px;">`, the margin of the table button.

## D4 — Outlook font fallback is a second, conditional `<style>` (completes F4.2)

F4.2 asks for "an `mso` style that replaces web fonts with the fallback stack". It is
`<!--[if mso]><style>…</style><![endif]-->` after the main `<style>`: only Outlook's Word
engine reads it, so CLAUDE.md's "one `<style>` block" holds for every other client. It sets
the text stack without the theme's web font families on body elements, the display stack
on `.mk-heading` and `.mk-wordmark` (the wordmark cell gained that class), and keeps the
monospace stack on `.mk-code`. It is output for every theme; without web fonts it repeats
the stacks.

## D5 — Dark mode and Outlook.com (completes F4.3)

The mockup's dark rules, plus: `.mk-divider` takes `dark.subtle`; Inline links
(`.mk-link`) take `dark.link`. Outside the media query, the same text-colour rules are
repeated with a `[data-ogsc] ` prefix (Outlook.com sets `data-ogsc` when it recolours
text). The banner keeps `brand` in dark mode, as in the mockups and 05-screens.md.

## D6 — Content checks (completes, T0 D3)

`checkContent` runs first in `renderHtml`: subject 1 to 200 characters without CR or LF;
preheader at most 140; `footerReason` at most 300 (an empty one is allowed, as the spec
sets no minimum); 1 to 30 blocks; heading 1 to 120; button label 1 to 40; button, link and
Inline link URLs `https:` or `mailto:` (`isAllowedUrl`), field `url` (`content` for an
Inline link); code `[A-Z0-9]{1,12}`; `group` an integer 0 to 6; an unknown block type is
field `type`. Lengths count code points. A link block's `lead` has no length rule in the
spec; it must only be a string. An empty `preheader` string renders no preheader div, as
an absent one.

## D7 — Free theme text inside CSS (completes)

Font stacks, web font families and URLs are free strings that land in a `style`
attribute or the `<style>` block; `cssValue` turns `"` into `'` and drops `< > { } ; \`,
so a theme cannot end the declaration, the rule or the element. Valid stacks are
unchanged. Colours are inserted as they are: `defineTheme` checks they are hex.

## D8 — Other choices (completes)

- Version stamp `<!-- mail-kit <VERSION> -->` is the first line of `<head>` (F6.5).
- `wordmarkSpacing` is a number in px (`letter-spacing:3px`); the mockup used a string.
- `@font-face` rules are built from `theme.webFonts` (`url('…') format('woff2')`); the
  mockup used a CSS string.
- Inline `{ bold }` renders `<strong style="font-weight:700;">`; Inline link renders
  `<a class="mk-link" style="color:{link};text-decoration:underline;">`.
- Divider: a 1 px `subtle` cell in a table with `margin:24px 0` (05-screens.md 5.1).
- Code `aria-label` is on the code cell (F2.6); display groups split from the start
  (`ABCDE`, group 2 → `AB CD E`).

## D9 — Tests (completes)

- Themes are built in `test/html/fixtures.ts` by `testTheme`, which fills T1's defaults
  and casts the brand (T0 D6); their colours are those of `spec/images/src/themes.json`,
  with `example.com` URLs. The three block sets are local fixtures shaped like the
  `magic-link`, `code` and `notice` samples (T4 owns the real ones).
- F4.3, F4.4 and the 4.5:1 part of F4.6 run in headless Chromium through playwright-core
  (`test/lint/browser.ts`): `$CCS_TEST_CHROME` when set, else the newest
  `chromium-headless-shell` under Playwright's cache; `colorScheme` set on the context
  (T0 D12); every request aborted, so the logo and fonts are never fetched. With no
  browser the test fails with the install command.

## Known limit (found work, not fixed)

A code shown with more than about 12 characters, group spaces included (`ABCDEFG` with
group 1, any 12-character code with a group), is wider than a 390 px phone's card (30 px
digits, 8 px letter spacing) and overflows it. F4.4's fixtures use
`482913` with group 3, which fits. A phone rule shrinking `.mk-code` would change the
mockup's phone image (F2.7), so it is left to the architect.
