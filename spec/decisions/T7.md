# T7 decisions: test sends and real-client checks

Date: 27 November 2026.

## D1: `package.json` entry

Only the `send-test` script (`node scripts/send-test.ts`) was added, as spec/06-api.md
requires. No other file outside T7's list changed.

## D2: Script shape

`scripts/send-test.ts` exports `parseArgs` and `sendTest(input, env, { fetch, sleep })`;
the CLI part runs only when the file is the entry point. Exit 2 on a missing input
(`RESEND_API_KEY`, `MAIL_KIT_TEST_FROM`, `--to`, `--theme`, `--sample`), an unknown theme,
sample or `--lang`, or an address outside the allow-list; exit 1 with the status only on a
non-2xx answer. The Resend body is never printed. `--lang fr|en` was added (default `fr`).

## D3: Allow-list

The spec says "Claude's own mailboxes" but a real address must not be committed. The list
comes from `MAIL_KIT_TEST_MAILBOXES` (comma separated, case-insensitive); an empty list
refuses everything. `--allow-any` bypasses it. Real sends set it from `vault address`.

## D4: 429

One retry after `retry-after` seconds (default 1 s when absent or invalid, capped at 120 s);
a second non-2xx stops with the status.

## D5: Key mapping

The vault holds `RESEND_API_KEY_MAIL_KIT` (sending-only) and also an older
`RESEND_API_KEY`. `vault run` exports both, so the real sends map explicitly:
`vault run --project claude -- sh -c 'RESEND_API_KEY="$RESEND_API_KEY_MAIL_KIT" node scripts/send-test.ts ...'`
with `MAIL_KIT_TEST_FROM=mail-kit-test@majordome.example`.

## D6: Real sends

All 6 pairs (majordome and dream-studio x magic-link, code, notice; `fr`) were sent to
Claude's vault mailbox: Resend answered 2xx for each and `vault mail list` shows the 6
arrivals. 6 sends, far under the free plan's daily limit.

## D7: Gaps (assumption 3 and 4, open question 2)

- **F8.3 Gmail web: blocked.** `vault mail` lists subjects only, so the mailbox cannot be
  opened in a web client. The vault's Gmail OAuth credentials belong to the owner's own
  mailbox (read with `gmail.metadata` scope): never used, per the task. No Gmail account
  of Claude's with a web sign-in exists, and no password for one is in the vault. Decision
  table row 3 (another mailbox Claude owns) has no web-capable candidate yet.
- **F8.4 Apple Mail: blocked.** In the sandbox guest, Mail opens on an "Add Account"
  wizard that the `.eml` files (built from the same renderMail output) do not get past; the
  wizard is not reachable through System Events, and Escape quits Mail. Claude's mailbox
  is Cloudflare Email Routing, with no IMAP, so no account can be added. Four sandbox runs,
  no usable screenshot.
- **F8.5 Outlook: blocked.** Outlook.com web needs an Outlook address Claude owns; the
  signup form was reached in the headless Chrome but not completed (it would need a new
  account with a password and, in practice, Microsoft's CAPTCHA or phone checks, which were
  not tried). Classic Outlook: not installed in the VM per assumption 4, not checked,
  open question 2 answered "no" on 27 Nov 2026.
- A follow-up is needed: a Claude-owned web mailbox (an Outlook.com or Gmail account made
  with Claude's address and phone-free verification, or an IMAP mailbox for Apple Mail).
