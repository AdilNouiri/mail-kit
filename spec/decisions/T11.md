# T11 decisions — Loopback `http:` links and release 0.1.1

Date: 27 November 2026.

## D1 — The scheme value `"http:loopback"`

`UrlScheme` gains `"http:loopback"`, which is not a real protocol: `isAllowedUrl` accepts
an `http:` URL only when that value is in `schemes` and the host passes the loopback
check. No list can hold a bare `"http:"`, so a caller can never open every `http:` URL by
mistake. `src/html/check.ts` is the only caller that passes it; `src/theme.ts` still
passes `["https:"]` and is unchanged, so theme URLs keep refusing every `http:` URL.

## D2 — How the host is checked "as written" and "as parsed" (F2.9)

The raw string must start with `http://` (ASCII case-insensitive); the authority is the
text after it up to the first `/`, `?` or `#`. The written host is that authority before
the port (`[...]` kept whole for IPv6), and what follows it must be empty or `:` and
digits. The URL passes only when the written host, lower-cased on ASCII letters only, is
`localhost`, `127.0.0.1` or `[::1]` AND equals the WHATWG parser's `hostname`. So
`LOCALHOST` passes; `127.1`, `0x7f.0.0.1`, `0177.0.0.1`, `2130706433`,
`[0:0:0:0:0:0:0:1]`, `[::ffff:127.0.0.1]`, `%6Cocalhost` and full-width letters (all
rewritten by the parser) and `localhost.` are refused. The existing whitespace and
control-character refusal runs first, so the parser never strips anything.

## D3 — Userinfo and backslashes refused outright

Any `@` in the written authority is refused, and so is a non-empty parsed `username` or
`password`, so an empty userinfo (`http://@localhost/`, `http://:@localhost/`) is refused
too. An `@` in the path, query or fragment stays allowed (`/@me`). Any `\` in a loopback
URL is refused: the parser reads it as `/` in `http:` URLs, other readers may not, and no
request origin holds one. `http:localhost/`, `http:/localhost/` and `http:///localhost/`
(which the parser all normalises to `http://localhost/`) fail the `http://` prefix or the
empty written host.

## D4 — Uppercase scheme accepted

`HTTP://localhost:8787/v` is accepted, as `HTTPS://` already was for `https:` (the
existing `isAllowedUrl` test): schemes are case-insensitive and F2.9 restricts the host,
not the scheme's case.

## D5 — Empty port

`http://localhost:/` passes (the parser drops the empty port and the host is exact). It is
not tested either way: no request origin is written so, and it reaches the same loopback
host.

## D6 — Tests compare with the `https:` rendering

`test/html/render.test.ts` and `test/text.test.ts` render the same blocks with an
`https:` address and with each loopback address and compare the outputs with the address
swapped, which proves "renders like an `https:` URL" for the button `href`, its VML
`href`, its fallback link, the link block and an inline link. The text test uses short
addresses so wrapping at 76 columns is the same for both.
