# T13 decisions: input hardening

Date: 28 November 2026.

## D1: Bidi controls are the whole Unicode Bidi_Control set

F2.10 names U+202A to U+202E and U+2066 to U+2069. `isAllowedUrl` also refuses the other
three Bidi_Control characters, U+061C, U+200E and U+200F: they reorder printed text the same
way and have no place in a URL. The zero-width set is the one F2.10 names (U+200B to U+200D,
U+2060, U+FEFF). Rejected: the named ranges only, which would leave the left-to-right and
right-to-left marks to mislead a reader.

## D2: Userinfo is read from the parser and from the written authority

A URL holds userinfo when the WHATWG parser returns a username or a password, or when the
text between `//` and the first `/`, `?` or `#` holds `@` (this catches the empty userinfo of
`https://@host/`, which the parser drops). The written check applies only when the parsed URL
has a host, so `mailto:alice@example.com` and an `@` in a path, query or fragment
(`https://cdn.example.com/logo@2x.png`) stay accepted. A `mailto://user@host` URL is refused
(the parser gives it a username). The loopback check of F2.9 now relies on these shared
checks for userinfo and `\` instead of its own.

## D3: `cssValue` strips `&` from font URLs too

`cssValue` is also applied to `webFonts[].url` inside the `<style>` block, where html entities
are not decoded. F1.7 asks `cssValue` to strip `&`, so a font URL whose query holds `&` loses
it, as it already lost `;`. No built-in theme has one (the rendered samples are byte for byte
unchanged, checked against `5400f0e`). Rejected: a second, URL-only sanitiser, which F1.7 does
not ask for.

## D4: `renderText` checks, `renderMail` does not check twice

`renderText` asserts the theme (F1.8) and runs `checkContent` (F2.12), then calls `textPart`,
which renders an already checked input. `renderMail` asserts the theme, lets `renderHtml` run
the content checks, then calls `textPart`, so a mail is checked once. `textPart` and
`assertDefinedTheme` are module exports, not package exports (`src/index.ts` is unchanged).

## D5: A non-object content is a `ContentError` on `content`

F2.11 says no input from untyped code throws anything but a `ContentError`; `null` or a string
as the whole content would have thrown a `TypeError` on `content.subject`. `checkContent`
refuses it with the field `content` and no block index. A paragraph or note whose visible
text (strings, `bold` and link texts joined) is empty after `trim()` is refused on `content`;
`trim()` also removes the no-break space, so a content of only U+00A0 is blank.

## D6: `footerReason` follows the data model: 1 to 300 characters

The data model (4.2) says an empty string is refused; a blank one (`" "`) stays accepted,
as the data model and F2.11 name only the empty string.

## D7: Two test files added to T13's files

F1.8 makes `renderText` refuse a theme `defineTheme` did not return, and `testTheme` now
calls `defineTheme`. Two tests outside the task's original files relied on cast themes and
failed. The coordinator added both files to T13 (28 November 2026); only the broken lines
changed:

- `test/text.test.ts`: its `theme(lang)` helper cast an object with empty colours; it now
  builds the theme with `defineTheme` from `majordomeInput`, with its own id, wordmark,
  `lang`, system font stacks and `footer`.
- `test/lint/compat.test.ts`, "keeps the generic family when the stack holds web fonts only":
  it passed `display: "'Gloock'"`, which `defineTheme` refuses (F1.5). The case is no longer
  reachable through a defined theme, so it now tests `fallbackStack` directly.

## D8: Review 1, B1: an unknown block type is quoted only when it is a string

The unknown-type message ran `JSON.stringify` on any value, which throws a `TypeError` on a
BigInt or a circular object, against F2.11's "nothing else". A string type is still quoted
(`unknown block type "image"`); any other value is named by its `typeof`
(`unknown block type of type bigint`). Both inputs are in the "nothing else" table.

## D9: Review 1, N1: the empty userinfo hidden behind extra slashes

The parser skips every `/` after an `http:` or `https:` scheme, so `https:///@evil.example/`
holds an empty userinfo that D2's "text after the first `//`" missed. The userinfo check now
reads the authority after all the slashes that follow the scheme. The loopback check of F2.9
keeps reading the authority right after `http://`, so `http:///localhost/` stays refused, as
before.

## D10: Review 1, N2: a hole in `webFonts` is a `ThemeError`

`map` skipped the holes of a sparse `webFonts` array, so they were never checked and the
frozen theme kept them. `Array.from` visits each index, and a hole fails as
`webFonts[<index>]` "must be an object".

## D11: Review 1, N6: a paragraph or note that draws nothing is blank

`trim()` kept U+200B and the other invisible characters, so a note of only U+200B passed. A
paragraph or note is now blank when its visible text holds only whitespace (`\s`), format
characters (`\p{Cf}`) and default-ignorable code points
(`\p{Default_Ignorable_Code_Point}`: U+00AD, U+034F, U+3164, variation selectors...). The
rule applies to paragraph and note content only, the text F2.11's blank check names; a
heading, a button label and `footerReason` keep their length rules. Rejected: a hand-written
list of code points, which would miss the rest of the default-ignorable set.
